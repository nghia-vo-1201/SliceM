# G-code dialect: Prusa Buddy family (MK4 / MK4S / Core One / Core One L)

Status: black-box research, 2026-10-14. Observed from PrusaSlicer 2.9.4 console output (MK4S and Core One L),
shipped config data, and public Prusa docs. Not directly observed = `unverified`. Plain MK4 and Core One (non-L)
were NOT sliced; they are inferred from shared profile structure and are `unverified`.

Firmware: Prusa-Firmware-Buddy (Marlin 2 fork). Slicer config: `gcode_flavor = marlin2`.

## 1. Overall file structure

IMPORTANT SURPRISE: the Buddy profiles default to `binary_gcode = 1`, so the default export is a **binary G-code (.bgcode)**: file starts with magic `GCDE`, blocks of metadata (`Producer`, `printer_model`, ...), thumbnails, print metadata, and compressed G-code blocks. SliceM must either emit plain-text `.gcode` (accepted by the printer; we forced `--binary-gcode=0` and inspected that) or implement the bgcode container. Plain text is the simple target. Whether the printer firmware accepts plain text for all uses: `unverified` on hardware (the profile exposes a switch, which indicates support).

Text layout (observed, 20 mm cube, 100 layers):
1. Header: `; generated by PrusaSlicer ...`, extrusion-width comments, thumbnails (16x16 QOI, 313x173 QOI, 480x240 QOI, 380x285 PNG listed in config).
2. Limits block: `M73 P0 R<min>` / `M73 Q0 S<min>`, `M201` accel, `M203` feedrates, `M204 P.. R.. T..`, `M205` jerk (X,Y,Z,E), `M205 J0.010` junction deviation, `M205 S0 T0`.
3. Cancel-object registration: `M486 S0`, `M486 A<name>`, `M486 S-1` (objects get `M486 S<i>` before their moves, `M486 S-1` for non-object moves like purge).
4. Start sequence (`;TYPE:Custom`), body, end sequence, trailer (`; objects_info`, filament used, estimated time normal/silent, full config as comments).

## 2. Initialisation requirements (observed order)

MK4S (Core One L differences in section 6):

| # | Command | Purpose |
|---|---|---|
| 1 | `M17` | enable steppers |
| 2 | `M862.1 P0.4 A0 F0` | nozzle check (diameter; A/F = abrasive and high-flow flags - flag meaning `unverified`) |
| 3 | `M862.3 P "MK4S"` (Core One L: `"COREONEL"`) | printer-model check |
| 4 | `M862.5 P2` | G-code level check (level 2) |
| 5 | `M862.6 P"Input shaper"` | firmware feature required |
| 6 | `M115 U<fw>` | authored-for firmware version |
| 7 | `M555 X Y W H` | print-area rectangle (origin + width/height), used by firmware to limit mesh/purge areas to the part |
| 8 | `G90`, `M83` | absolute XYZ, relative E |
| 9 | `M140 S60`; `M104 T0 S170`; `M109 T0 R170` | bed on; nozzle to 170 (low "probing" temperature so oozing does not touch bed), wait (R = wait heating or cooling) |
| 10 | `M84 E` | disable E motor (before homing/probing) |
| 11 | `G28` | home all, no mesh |
| 12 | `G1 X.. Y-4 Z5`, `M302 S155`, `G1 E-2 F2400` | go to nozzle-cleaning spot, allow cold extrusion down to 155 C, retract |
| 13 | `G29 P9 X10 Y-4 W32 H4` | nozzle clean / pre-probe on the purge-area strip (parameter meaning `unverified`; Prusa docs for G29 give no P modes) |
| 14 | `M106 S100`, `G0 Z40`, `M190 S60`, `M107` | cool nozzle with fan, wait bed |
| 15 | `G29 P1`, `G29 P1 X0 Y0 W50 H20 C`, `G29 P3.2`, `G29 P3.13`, `G29 A` | mesh bed levelling: invalidate, probe print area, probe near purge, interpolate, extrapolate, activate (step meanings are my reading of the inline comments in the output) |
| 16 | `M104 S230`, `G0 X0 Y-4 Z15`, `M109 S230` | final first-layer temp, wait |
| 17 | `G92 E0`, `M569 S0 E` | zero E; extruder to spreadCycle (Prusa docs: M569 S0 = spreadCycle/stealthChop off) |
| 18 | purge: `G1 E2 F2400`, `G0 E7 X15 Z0.2 F500`, then ~3 purge segments, wipe with `Z0.05` then `Z0.2` | prime line on the bed edge |
| 19 | `G92 E0`, `M221 S100`, `G21`, `G90`, `M83` | reset; flow; explicit units and modes again |
| 20 | `M572 S0.036` | pressure advance (docs: D extruder, S value, 0 disables) |
| 21 | `M142 S36` | heatbreak cooling target temperature (docs: S = target in C) |
| 22 | `M107` | fan off for layer 1 |

Core One L adds chamber/bed fans: `M106 P5 R A125 B10` (bed fan, fade), `M141 S20` (chamber temperature target; not described in the Buddy doc page, `unverified`), `M106 P3 N76 G3`, `M190 R60`, `M107 P5`, `M591 S0` / `M591 R` (disable and restore stall detection around the purge), `G1 Z20` bed lift before probing. Purge/probing x-coordinates are near the right of the 300 mm bed (X 150..249).

## 3. Per-layer structure

Markers: `;LAYER_CHANGE`, `;Z:<z>`, `;HEIGHT:<h>`, `;BEFORE_LAYER_CHANGE`, `G92 E0.0`, `;<z>`, `;AFTER_LAYER_CHANGE`, `;<z>`, then `;TYPE:<feature>`, `;WIDTH:<w>`. `M74 W<grams>` per layer on MK4S (mass on bed, for input-shaper tuning per the docs). `M73` progress as on legacy. `M201 X.. Y..` rewrites max accel each layer on MK4S (profile formula based on extruded weight). `M486 S<i>` brackets object moves.

Retraction/travel: `G1 E-.7 F2100` (MK4S) / `F2700` (Core One L), then a travel that CARRIES Z: `G1 X.. Y.. Z<z+0.2> F18000` (z-hop 0.2 combined into the XY move, arrival at layer Z via `G1 Z<z> F720` (MK4S) / `F480` (Core One L)), then `G1 E.7 F1500` deretract. Travel 300 mm/s on MK4S, 500 on Core One L. Moves can also be at layer-change time: `G1 X Y Z+0.32` ramp (slope). Acceleration via `M204 P<print> T<travel>` (Marlin 2 style P/R/T). Fan: `M106 S<n>`; temperature: `M104 S220 ; set temperature` at layer 2 on MK4S. Wipe is off (`wipe = 0`) for these profiles; retract_before_wipe 80%. No `M900`; pressure advance is `M572` (set once in start; filament profiles may change it).

## 4. End-of-job (observed order, MK4S)

1. `M486 S-1`, retract `G1 E-.7`, `M107`
2. `G1 Z21 F720` lift (layer top + 1)
3. `M104 S0`, `M140 S0`, `M107`
4. `G1 X241 Y170 F3600` park
5. `G1 Z43 F300`, `G4`
6. `M572 S0` reset PA, `M593 X T2 F0` and `M593 Y T2 F0` (disable input shaper)
7. `M84 X Y E` disable motors EXCEPT Z (Z kept energised so the bed/gantry does not drop; reasoning is mine, `unverified`)

Core One L: heaters off then `M141 S0` (chamber), `M107`, `M107 P3`, `M107 P5` (extra fans), `G1 X242 Y211 F10200` park, `G4`, `M572 S0`, `M84 X Y E`. No second Z move and no `M593` lines in this profile.

## 5. Colour change / pause (MOST IMPORTANT)

Config data: `color_change_gcode = M600` + `G1 E0.3 F1500 ; prime after color change` (same text in MK4S and Core One L profiles; other filament-variant profiles in the bundle use 0.3 to 0.5), `pause_print_gcode = M601`.

Observed (colour change at print_z 10, MK4S):
```
;AFTER_LAYER_CHANGE / ;10 / M74 W...
G1 Z10 F720
;COLOR_CHANGE,T0,#FF8000
M600
G1 E0.3 F1500 ; prime after color change
;TYPE:Perimeter
```
Core One L is the same with `F480` Z feed. Pause: `;PAUSE_PRINT` then `M601`, emitted while the nozzle is still hopped (before the lowering `G1 Z10`), after which a deretract `G1 E.7` follows. Because the retract was done before travel and `M600` follows the final lowering, filament stays retracted into `M600`; the following `G1 E0.3` prime covers it.

Semantics (public Prusa docs, "Buddy firmware-specific G-code commands"): `M600` = "Filament change pause" with params `E` retract distance, `Z` Z move, `X`/`Y` move to position, `U` retract for removal, `L` extrude for insertion, `B` beep count (-1 = indefinite), `T` toolhead, `A` use automatic spool join if configured otherwise manual change. Omitted arguments use defaults. `M601` = pause print with no parameters listed. The page does not state whether the user dialogue, temperature hold, or auto-resume occur, so those are `unverified` (not observed on hardware). For SliceM: emitting bare `M600` is sufficient and matches Prusa's own profiles; re-prime afterwards.
Distinctions: M600 = filament swap flow (the firmware drives unload/load), M601 = pause only. Full MMU/"AUTO" changes are out of scope.

## 6. Differences between MK4S and Core One L (observed)

| Item | MK4S | Core One L |
|---|---|---|
| Bed / height | 250 x 210 / 220 | 300 x 300 / 330 |
| Kinematics | Z moves the gantry (cartesian-ish i3) | CoreXY, Z moves the bed (Z upward means bed lowers; `unverified` against docs) |
| Chamber | none | `M141 S20/S0`, enclosed with chamber fans `M106 P3`, bed fans `P5` |
| Travel speed | 300 | 500 |
| Accel (P/T) | 4000 / 4000 | 7000 / 6000 |
| Retract | 0.7 @ 35 mm/s | 0.7 @ 45 mm/s |
| Per-layer M74/M201 | yes | no (M201 once) |
| Park | X241 Y170 | X242 Y211 |
| Start | no bed fans | bed-fan fade, Z20 lift, stall detection off during purge |

## 7. Differences from the legacy family (summary)

Binary G-code default; `M862.5/.6`, `M555`, `M486`, `M74`, `M142`, `M572` (PA), `M569`, `M302`, `M84 E` pattern; `G29 P..` mesh sequence with nozzle cleaning at low temp; `M109 R`; `marlin2` flavor with junction deviation; Z-hop combined into XY travel; `M204 P/R/T`; steppers not fully disabled (`M84 X Y E`). Legacy uses `G80`, `M900 K`, `M907`, jerk-only, `M84` all.
