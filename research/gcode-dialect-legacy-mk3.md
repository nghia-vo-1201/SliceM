# G-code dialect: Prusa legacy family (MK3 / MK3S / MK3S+)

Status: black-box research, 2026-10-14. Everything below was observed from
PrusaSlicer 2.9.4 console output, shipped config data, or public Prusa docs.
Items not directly observed are marked `unverified`.

Firmware: Prusa-Firmware (Marlin derivative). Slicer config: `gcode_flavor = marlin`,
`binary_gcode = 0` (plain-text `.gcode` is the native output; no binary format).

## 1. Overall file structure (observed, MK3S, 20 mm cube, 0.20 mm layers, 100 layers)

1. **Header**: one `; generated by PrusaSlicer ...` line, a few `; ... extrusion width = ...` comment lines.
   Thumbnails (160x120 PNG, base64 in `; thumbnail begin/end` blocks) are embedded in the header.
   Viewers/Printer UI use them for previews; the printer does not need them.
2. **Limits block** (executable): `M73` progress init, `M201` max accel, `M203` max feedrate, `M204` accel,
   `M205` jerk, `M205 S0 T0` min rates. These are emitted from the machine-limits config, before the start sequence.
3. **Object markers**: `; printing object <name> id:0 copy 0` / `; stop printing object ...` comments (viewer/cancel-object use; not firmware commands on this family).
4. **Start sequence** (`;TYPE:Custom`): see section 2.
5. **Body**: per layer, see section 3.
6. **End sequence** (`;TYPE:Custom`): see section 4.
7. **Trailer**: `; objects_info`, `; filament used [mm]/[cm3]/[g]`, cost, estimated time (normal and silent), then
   `; prusaslicer_config = begin ... end` containing the complete config as comments (about 14k lines of comments in this file; the file was 23k lines in total, mostly this plus thumbnails).

Extrusion is relative (`M83`), coordinates absolute (`G90`). Observed `use_relative_e_distances = 1`.

## 2. Initialisation requirements (order observed)

| # | Command | Purpose |
|---|---|---|
| 1 | `M73 P0 R<min>` / `M73 Q0 S<min>` | progress + time-remaining for normal (P,R) and silent (Q,S) modes (per Prusa docs: P percent, R remaining, Q/S silent equivalents, C/D time to next change/pause) |
| 2 | `M201`, `M203`, `M204`, `M205` | set accel / feedrate / jerk limits |
| 3 | `M862.3 P "MK3S"` | printer-model compatibility check; firmware warns/pauses on mismatch |
| 4 | `M862.1 P0.4` | nozzle-diameter check |
| 5 | `M115 U<fw version>` | declare the firmware version the file was authored for; if the printer is older it pauses ~30 s and prompts to upgrade (Prusa docs) |
| 6 | `G90`, `M83` | absolute XYZ, relative E (set explicitly) |
| 7 | `M104 S<t>`, `M140 S<t>` | start both heaters without blocking (nozzle first-layer temp 215, bed 60 for PLA test) |
| 8 | `M190 S<bed>` then `M109 S<nozzle>` | wait bed, then wait nozzle (S = wait only when heating; Marlin docs) |
| 9 | `G28 W` | home all axes WITHOUT the firmware's own mesh levelling |
| 10 | `G80 X.. Y.. W.. H..` | mesh bed levelling restricted to a window around the part (Prusa docs: probe area X,Y origin, W,H size; `N` points, `C` retries) |
| 11 | `G1 Z0.2`, `G1 Y-3`, `G92 E0`, intro line `G1 X60 E9 F1000`, `G1 X100 E12.5` | prime: purge a line outside the part area |
| 12 | `G92 E0`, `M221 S95` | reset E, flow factor (filament profile) |
| 13 | `M907 E430` | extruder motor current (reset to default at end with `M907 E538`) |
| 14 | `G21`, `G90`, `M83` | repeat units/positioning explicitly |
| 15 | `M900 K<x>` | Linear Advance K (from filament profile; two lines, last wins) |
| 16 | `M107` | fan off before layer 1 |

Cold start is not handled: heaters are set in the sequence above. Fan is off for first layer
(`disable_fan_first_layers = 1`); `M106 S<0-255>` appears from layer 2.

## 3. Per-layer structure

Layer change markers (comments the viewer relies on): `;LAYER_CHANGE`, `;Z:<z>`, `;HEIGHT:<h>`,
and on layers after the first `;BEFORE_LAYER_CHANGE`, `G92 E0.0`, `;<z>`, then after the move `;AFTER_LAYER_CHANGE`, `;<z>`.
(The `BEFORE/AFTER` markers come from the profile's layer-change custom G-code, so they are profile data, not mandatory.)
Feature markers: `;TYPE:Skirt/Brim`, `Perimeter`, `External perimeter`, `Solid infill`, `Internal infill`, `Top solid infill`, `Custom`; `;WIDTH:<mm>`; `;WIPE_START` / `;WIPE_END`.

Travel/retract pattern (observed): retract `G1 E-.8 F2100` (retract_length 0.8, speed 35 mm/s), Z-hop `G1 Z<z+0.4> F720` (retract_lift 0.4, travel_speed_z 12), travel `G1 X Y F10800` (180 mm/s), lower `G1 Z<z>`, deretract `G1 E.8 F2100`.
Wipe-on-retract is enabled (`wipe = 1`): retraction is done as negative-E moves along the previous path between `;WIPE_START` and `;WIPE_END`.
Per-feature acceleration via `M204 S<n>`; feedrate set with a bare `G1 F<f>` before a run of extrusions.
Fan: `M106 S<n>` between layers (cooling slowdown / fan curve); `M107` at end of layer 1. Mid-print temperature: `M104 S<t>` at layer 2 (profile first-layer vs other-layer temperature).
Progress: `M73` lines scattered through the body (both P/R and Q/S forms).
Z handling: Z is only moved by explicit `G1 Z..` hops and layer changes; no `G1 Z` is combined with XY in this family's output.

## 4. End-of-job (observed order)

1. Final retract (`G1 E-.56 F2100`, partly done during wipe), `M107` fan off
2. `G1 Z21 F720` (lift: layer-top + 1 mm for a 20 mm part)
3. `G1 X0 Y200 F3600` park
4. `G1 Z69 F720` raise further
5. `G4` dwell (empty = wait for moves to finish)
6. `M221 S100`, `M900 K0`, `M907 E538` (reset flow, linear advance, motor current)
7. `M104 S0` nozzle off, `M140 S0` bed off, `M107` fan off
8. `M84` disable all steppers

## 5. Colour change / pause (MOST IMPORTANT)

Config data (identical in all profiles examined): `color_change_gcode = M600` followed by `G1 E0.3 F1500 ; prime after color change`
(a small extrusion value, 0.3 mm for the MK3S profile; other Prusa filament-variant profiles in the bundle use 0.3 to 0.5);
`pause_print_gcode = M601`; `template_custom_gcode` empty.

Observed emission (MK3S, colour change inserted at print_z 10 via 3MF, see Provenance):
```
;AFTER_LAYER_CHANGE
;10
G1 E-.8 F2100          retract + Z hop to 10.4 + travel + Z back to 10
G1 Z10.4 F720 ... G1 Z10 F720
G1 E.8 F2100           deretract (done BEFORE the M600)
;COLOR_CHANGE,T0,#FF8000
M600
G1 E0.3 F1500 ; prime after color change
```
The marker comment `;COLOR_CHANGE,T<tool>,<#rrggbb>` is emitted immediately before `M600`; for pauses it is `;PAUSE_PRINT` before `M601`. The change is inserted at the start of the layer whose Z equals the requested height (layers below stay in the old colour). In the pause case `M601` is emitted while the nozzle is still hopped (before the lowering `G1 Z10`); in the colour-change case the nozzle has already lowered to layer Z.

Semantics (Prusa public docs, help.prusa3d.com "Prusa firmware-specific G-code commands"):
- `M600 [X Y Z E L]`: "Filament change"; X park X default 211, Y park Y default 0, Z relative lift default 2, E initial retract default -2, L later retract for removal default -80. Also used by the runout-sensor process.
- `M601 [X Y Z S]`: pause print; parks at X default 50, Y default 190, Z raise default 20; `S` sets values without pausing.
- Whether the printer waits for the user, keeps the nozzle hot, and resumes on button press is NOT described on that page. The firmware's well-known behaviour (retract, park, unload prompt, load prompt, purge, "colour OK?" confirmation, resume) is `unverified` here (not observed on hardware, not documented in the pages read). The slicer-side requirement is only: emit `M600`; the printer owns the park/unload/load dialogue.
- Distinction: `M600` = filament change (unload + load dialog); `M601` = plain pause (no filament swap procedure). `M602` = resume (listed, undescribed) - `unverified`.
- The trailing `G1 E0.3 F1500` after `M600` is a slicer-side prime to compensate for the filament pulled back; it is part of the profile text, so SliceM should author its own and tune it.

## 6. Differences vs Buddy family (see companion doc)

See `gcode-dialect-buddy-mk4-coreone.md` section 7 for the full table. Headlines: no binary G-code; no `M862.5/M862.6`; no `M486`, `M74`, `M555`, `M142`, `M572`; mesh levelling is `G80` not `G29 P..`; LA is `M900 K`, not `M572`; Z-hop is a separate `G1 Z` move; jerk based (no junction deviation); end sequence uses `M84` for all motors and sets `M900 K0`.

## 7. Machine facts (from shipped profiles, `PrusaResearch.ini` and slicer config export)

| Fact | MK3 / MK3S / MK3S+ (0.4 nozzle) |
|---|---|
| Bed | 250 x 210 mm, origin 0,0 |
| Max print height | 210 mm |
| Nozzle | 0.4 (also 0.25, 0.6, 0.8 variants) |
| Filament diameter | 1.75 mm |
| Layer height range | 0.07 to 0.25 mm |
| Temperatures in default PLA profile | nozzle 215 first / 210 later, bed 60; absolute min/max limits: `unverified` (not in profile; firmware limits not read) |
| Max feedrate | X/Y 200, Z 12, E 120 mm/s (normal); silent X/Y 100 |
| Max accel | X/Y 1000 (silent 960), Z 200, E 5000, extruding 1250, travel 1500 mm/s^2 |
| Jerk | X/Y 8, Z 0.4, E 4.5 mm/s |
| Retraction | length 0.8 mm, speed 35 mm/s, lift 0.4 mm, wipe on |
| Firmware retraction | off (`use_firmware_retraction = 0`) |
| Enclosed | No (open frame) - general knowledge, `unverified` against a doc |
| Max volumetric speed (PLA profile) | 15 mm^3/s |
| MK3 vs MK3S | MK3S profile inherits MK3, differing in model id (`MK3S`) used by `M862.3`; the MK3 `printer_model` check string is `MK3`; MK3S+ shares the MK3S profile. Distinct hardware differences: `unverified` |
